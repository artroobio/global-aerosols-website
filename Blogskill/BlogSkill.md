## TRIGGER COMMAND
When the user says: **"execute BlogSkill"** (with no number)
→ Auto-select the next topic in rotation order
→ Read state.json to find last_topic_id and rotation_index
→ Pick the next unwritten topic from the next category in rotation

When the user says: **"execute BlogSkill [number]"**
→ Write the specific topic with that ID from topics.json

When the user says: **"execute BlogSkill batch [X-Y]"**
→ Queue topics X through Y and write them in order

## EXECUTION PIPELINE (run in this exact order)

### STEP 1 — READ STATE
Read `Blogskill/state.json`.
Identify:
- `rotation_index` → which category is next (0–4)
- `written_ids` → skip any IDs already written
- `last_topic_id` → for reference

Load topics.json and select the correct next topic.

From topics.json:
- Filter by the current rotation category
- Pick the lowest ID not in `written_ids`
- Extract: title, slug, primary_keyword, supporting_keywords, audience, internal_links, image_descriptors

Every article must carry a deliberate internal-linking structure across THREE tiers.

**Tier 1 — Contextual in-body links (minimum 3–4 per article)**
Weave at least 3–4 internal links naturally into the body text (NOT just the footer),
each on relevant anchor text where the topic genuinely connects. Sources:

- **At least one link to the relevant category/landing page** for the topic, e.g.:
  - Aerosol Technology topic → `/aerosol-technology-and-formulations`
  - Propellants & Valves topic → `/aerosols`

  - Personal Care Aerosols topic → `/cosmetics-and-personal-care-aerosols-guide`

Place these where the reader would naturally want more depth — never a dumped list.

### D. CONTENT RULES (NON-NEGOTIABLE)

1. **Minimum 2000 words** of actual body content — technical aerosol topics that compete in search require this depth. 1200 is the hard floor; 2500–3000 is the target for pillar-style or highly competitive topics.
2. **Technical accuracy only** — verified facts, no speculation whatsoever
3. **All technical claims must be grounded in established science only** — published aerosol science, peer-reviewed research, recognised industry standards (ASTM, ISO, DOT, NFPA, EU Aerosol Directive, BIS), or well-documented industrial practice. Do not state mechanisms, performance claims, or material properties unless they are verifiable from authoritative sources. If a claim cannot be substantiated from established literature, omit it entirely rather than qualify it with hedging language ("may", "could", "is believed to"). Hedged speculation dressed as technical content is treated the same as outright speculation — both are prohibited.
4. **NO exact formulation percentages, ingredient ratios, or proprietary dosages** — discuss chemistry, mechanisms, ingredient classes, process parameters, and performance strategies only. For technical articles: describe the type of ingredient, its function, its selection criteria, and performance trade-offs. Never state "X% of ingredient Y" or "add Z grams per litre". This applies to all five categories without exception. The value this blog delivers is expert understanding — not recipes.
5. **Every H2/H3 section starts with 3–4 line explanatory paragraph** — no exceptions
6. **Bullet points** used ONLY after the paragraph — for listing, summarising, or key takeaways
7. **Tables** used wherever comparison data exists: types, grades, standards, properties, specs
8. **FAQ** minimum 6 questions — technically accurate 2–4 sentence answers
9. **Tone:** Technical + Educational + Problem-solving — premium, authoritative
10. **IP protection:** Focus on aerosol engineering strategy and chemical mechanisms; never reveal proprietary blend information or specific formulation recipes
11. **Table of Contents** included for all articles with 5 or more H2 sections
